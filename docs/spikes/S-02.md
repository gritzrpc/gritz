# S-02: RPC errors during worker replacement

- Date: 2026-10-02.
- Environment: [shared environment](README.md).
- Load: 64 independent channels, unary Echo, Ruby client, ten seconds per condition.
- Retries: disabled with `grpc.enable_retries=0`.

The runner waits for all workers to report ready, starts load, then drains one
worker after two seconds. Replacement conditions wait for a fifth worker to
report ready before sending TERM to the old worker. Each server uses
`poll_period=1` for grpc shutdown. This is a raw grpc experiment.

```sh
# Select tcp_migrate_req when creating the container:
# docker run --sysctl net.ipv4.tcp_migrate_req=0 ...
# docker run --sysctl net.ipv4.tcp_migrate_req=1 ...
WORKERS=4 DURATION=10 DRAIN=1 ruby spikes/s01_reuseport/run.rb
WORKERS=4 DURATION=10 DRAIN=1 REPLACE=1 ruby spikes/s01_reuseport/run.rb
WORKERS=4 DURATION=15 DRAIN=1 REPLACE=1 MAX_CONNECTION_AGE_MS=10000 \
  ruby spikes/s01_reuseport/run.rb
```

| Condition | tcp_migrate_req | Replacement first | Successful RPCs | Errors |

| [A](results/s02_a_linux.json) | 0 | No | 172,714 | 4 CANCELLED |
| [B](results/s02_b_linux.json) | 1 | No | 148,739 | 9 CANCELLED |
| [C](results/s02_c_linux.json) | 0 | Yes | 160,437 | 13 CANCELLED |
| [D](results/s02_d_linux.json) | 1 | Yes | 143,899 | 6 CANCELLED, 1 UNAVAILABLE |

The [15-second connection-age variant](results/s02_d_connection_age_linux.json)
completed 235,049 RPCs with 12 CANCELLED errors. Its new worker first received a
response 1.983 seconds after load started, near replacement time. This proves
that a replacement can receive reconnected traffic; it does not measure the
effect of connection age separately from the old listener closing. In the
unlimited-age D run, the new worker received no RPCs during the measurement.

**The tested condition D fails the zero-error requirement.** No claim is made
that `tcp_migrate_req` prevents in-flight RPC cancellation: socket queue
migration and gRPC shutdown are different mechanisms. The experiment does not
isolate the cause of each error, and the replacement timing alone is insufficient
to guarantee successful client calls.

Before enabling a production cluster: reproduce with the prescribed 60-second
ghz scenario, isolate listener resets from RPC cancellation, vary the graceful
deadline, and measure connection rebalancing separately. If the zero-error gate
still fails, evaluate `port_per_worker` behind a proxy as required by the roadmap.
ADR 002 is Proposed; a retry policy must not conceal failures in this gate.
