# S-07: Rails preload and proportional memory

- Date: 2026-10-02.
- Status: Pending; no PSS or USS measurement is claimed.

The required representative Rails application and ten-minute load experiment
have not been created or run. Raw grpc CPU measurements cannot establish Rails
Copy-on-Write savings, and macOS RSS cannot substitute for Linux PSS.

Run the future experiment in Linux with a representative Rails application
(several dozen models and dependencies), fixed four-worker load, and three
separate conditions: no preload, preload, preload plus `Process.warmup`.
After ten minutes, record each PID's PSS, USS and RSS:

```sh
smem -k -c "pid name uss pss rss"
cat /proc/PID/smaps_rollup
```

Also record the single-process RSS baseline, Rails/Ruby/gem versions, kernel,
worker request counts and whether DB connections were disconnected before
fork. Evaluate additional-worker PSS against 40% of baseline single-process
RSS; retain the raw samples rather than a bare pass/fail statement.

The Linux devcontainer includes smem, but no Rails memory-efficiency guarantee
is established by this initial single-process release.
