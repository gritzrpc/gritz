# S-04: Experimental grpc fork support

- Date: 2026-10-02.
- Environment: [shared environment](README.md), Linux, grpc 1.83.0.

Start S-01's server in a separate process, then run:

```sh
WORKERS=1 ruby spikes/s01_reuseport/server.rb
# In a second terminal:
timeout 20 ruby spikes/s04_grpc_fork_support/probe.rb
timeout 10 ruby spikes/s04_grpc_fork_support/bidi.rb
```

The probe sets `GRPC_ENABLE_FORK_SUPPORT=1` before requiring grpc, performs a
unary RPC in the parent, calls prefork, forks, and pairs postfork_child and
postfork_parent. The child creates a new RpcServer and successfully responds to
a second unary RPC. Prefork took **0.0858 ms** in this single sample.

With an active bidi stream, prefork rejected the operation with the expected
message about background threads and bidirectional streams not being fork safe.
Raw results: [unary and child server](results/s04_linux.json),
[active bidi](results/s04_linux_bidi.json).
Primary source: [grpc 1.83.0 fork APIs and guards](https://github.com/grpc/grpc/blob/v1.83.0/src/ruby/ext/grpc/rb_grpc.c).

This is a feasibility pass for one client-only parent sequence, not support for
forking an active server. Repeated fork cycles, deadlines, in-flight unary
requests, inherited-channel reuse and version compatibility remain untested.
Keep clean master as the default and this mode experimental.
